# English_Post_Lit — посты с иллюстрацией и отрывком из классики

Репозиторий публикует в Telegram-канал один пост за раз: **иллюстрация из книги + 3–4 предложения
с пропусками + варианты слов для каждого пропуска**. Ответ, короткое пояснение и источник спрятаны
под спойлером. В посте нет ни заголовков, ни уровней, ни иконок, а подпись набрана обычным шрифтом.

Опросов в этом репозитории нет вообще: он целиком посвящён постам с картинками и не зависит от других.

Пример подписи под картинкой:

```
The Caterpillar took the hookah out of its mouth, and (1) ____ her in a (2) ____, sleepy voice.

1) told / addressed / spoke
2) lazy / languid / tired

[под спойлером: 1 addressed · 2 languid / пояснение / — Lewis Carroll, Alice's Adventures in Wonderland]
```

## Как это устроено

- **Откуда книги.** Из проекта [Standard Ebooks](https://github.com/standardebooks): выверенные издания
  в общественном достоянии, которые лежат прямо на GitHub. Поэтому GitHub Actions получает их без блокировок.
  Проект Gutenberg я пробовал первым, но он не отдаёт файлы облачным серверам (ошибка 503), и от него пришлось отказаться.
- **Картинка и отрывок.** В этих изданиях у каждой иллюстрации есть описание того, что на ней нарисовано.
  По описанию Gemini выбирает из окружающего текста 3–4 предложения, которые картинка показывает.
  Отрывок обязан дословно совпасть с текстом книги, поэтому выдуманных цитат не бывает.
  Пропуски и неверные варианты тоже делает Gemini, а второй независимый запрос проверяет, что ответ однозначный.
- **Формат картинки.** Всегда 16:9 (1280×720), **без размытого фона**:
  1. `crop`: если пропорции близки к 16:9, картинка слегка подрезается по краям (до 18%), без полей;
  2. `mat`: гравюра или рисунок на светлой «бумаге» целиком лежит на ровном фоне того же цвета, шва не видно;
  3. `frame`: цветная картинка во весь лист кладётся целиком в тёмную рамку в тон картинки.
- **Очередь.** Отрывки выдаются в случайном порядке без повторов до конца круга, потом банк перемешивается заново.
  Новые отрывки сами встают в очередь.
- **Два независимых workflow:** публикация поста (`post.yml`) и пополнение банка (`build.yml`).
  Менять и запускать их можно по отдельности.

## Книги в комплекте

В `books.json` пять иллюстрированных книг с картинками старых изданий:

| Книга | Иллюстрации | Картинок |
|---|---|---|
| Alice's Adventures in Wonderland | Джон Тенниел | около 40 |
| Through the Looking-Glass | Джон Тенниел | около 50 |
| Just So Stories (Киплинг) | рисунки самого автора | около 45 |
| The Return of Sherlock Holmes | Сидни Пэджет | около 10 |
| The Book of Wonder (Дансени) | Сидни Сайм | около 9 |

Всего это примерно 150 картинок, но часть отсеется при проверке (мелкие, нет подходящего текста рядом).
Это 3–5 месяцев при одном посте в день. Банк нужно будет расширять: добавьте книги в `books.json`
(как, см. ниже). Роберта Гуда Пайла, «Белого Клыка», Шекспира и Байрона здесь нет: у них нет подходящих
иллюстрированных изданий в этом источнике.

## Настройка (один раз)

**1. Бот и канал.** @BotFather → `/newbot` → токен. Создайте канал и добавьте бота администратором
с правом публиковать. Для проверки используйте тестовый бот и закрытый тестовый канал.
Идентификатор закрытого канала: опубликуйте в нём любое сообщение и откройте в браузере
`https://api.telegram.org/bot<ТОКЕН>/getUpdates`, нужное значение стоит в `"chat":{"id":-100…`.
У публичного канала можно указать `@username`.

**2. Ключ Gemini.** https://aistudio.google.com → Get API key. Карта не нужна.
Лимиты бесплатного тарифа обычно считаются на проект, поэтому для этого репозитория лучше завести ключ
в отдельном проекте.

**3. Репозиторий.** На github.com: New repository с именем **English_Post_Lit**, Public.
Add file → Upload files → перетащите всё содержимое папки, включая скрытую папку `.github`.
Проверьте, что в репозитории есть `.github/workflows/post.yml` и `.github/workflows/build.yml`.
Если их нет: Add file → Create new file, введите путь `.github/workflows/post.yml` и вставьте содержимое
(то же для `build.yml`).

**4. Секреты** (Settings → Secrets and variables → Actions → New repository secret):

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHAT_ID` | id канала (`-100…`) или `@username` |
| `GEMINI_API_KEY` | ключ из AI Studio |

## Первый запуск (вручную)

Вкладка Actions. Слева будут два workflow.

1. **English_Post_Lit — пополнение банка** → Run workflow → `count = 5`. В логе для каждой загруженной книги
   видно, сколько в ней картинок и сколько годится, а в конце написано, как подогнаны картинки (`crop`, `mat`, `frame`).
2. **English_Post_Lit — публикация поста** → Run workflow → в канале появляется пост.
3. Посмотрите 10–20 постов: подходит ли картинка к тексту, нет ли неоднозначных вариантов.
4. Наполните банк: запускайте пополнение с `count = 20` или включите ночное автопополнение (ниже).
   За один запуск берутся 3 книги, в которых отрывков меньше всего, поэтому банк растёт равномерно.

## Автоматический режим

В обоих файлах в `.github/workflows/` расписание закомментировано. Чтобы включить, откройте файл, уберите `#`
перед блоком `schedule:` и Commit:
- `post.yml`: `cron: "0 15 * * *"` — один пост в день в 15:00 UTC. Для двух постов добавьте вторую строку `cron`
  и поставьте переменную `POSTS_PER_DAY` = 2.
- `build.yml`: `cron: "30 2 * * *"` — ночное пополнение банка до `PASSAGES_TARGET`, по 20 отрывков за ночь.

Время в `cron` указано в UTC. Расписания работают только с основной веткой (`main`).

## Как добавить книгу

Нужны только иллюстрированные издания: у Standard Ebooks большинство книг без картинок.
1. Откройте github.com/standardebooks и найдите книгу. Имя репозитория видно в адресе, например
   `beatrix-potter_short-fiction`.
2. Добавьте строку в `books.json`: `{"id": "имя-репозитория", "title": "Название", "author": "Автор"}`.
3. Запустите пополнение. Если в логе у книги «годных: 0», у неё нет подходящих иллюстраций.

Проверено, что иллюстрации есть, например, у `beatrix-potter_short-fiction` (сказки Поттер: язык проще,
качество картинок ниже) и `edward-lear_nonsense-books` (стихотворения-небылицы, это другой жанр).

## Настройки

| Что | Как |
|---|---|
| Размер банка | Variable `PASSAGES_TARGET` (по умолчанию 365) |
| Число постов в день | Variable `POSTS_PER_DAY` и столько же строк `cron` |
| Язык пояснений | Variable `EXPLANATION_LANG` (по умолчанию `Russian`) |
| Другая модель Gemini | Variable `GEMINI_MODEL` (по умолчанию `gemini-flash-latest`) |
| Что под спойлером | `SHOW_EXPLANATION`, `SHOW_SOURCE` в `common.py` |
| Формат картинки | `CANVAS_W`, `CANVAS_H` в `common.py` (для 21:9: 1280 и 549) |
| Строже к подрезке | `CROP_MAX_LOSS` в `common.py`: меньше значение, меньше подрезки и больше фона вокруг картинки |

Variables: Settings → Secrets and variables → Actions → вкладка Variables.

## Если что-то не так

- **«книга не скачалась»:** проверьте имя репозитория в `books.json` (оно должно совпадать с адресом на github.com/standardebooks).
- **«Новых иллюстраций не осталось»:** все картинки из книг в `books.json` уже использованы. Добавьте книги.
- **`Gemini API 404`:** имя модели устарело. Посмотрите актуальное имя Flash-модели в AI Studio и задайте `GEMINI_MODEL`.
- **«остановка» или `429`:** исчерпан лимит бесплатного тарифа. Прогресс сохранён, продолжайте на следующий день.
- **«Банк отрывков пуст»:** сначала запустите пополнение.
- **Автопубликация остановилась:** GitHub отключает расписания в публичном репозитории после 60 дней без активности.
  Бот коммитит очередь при каждом посте, и это должно считаться активностью, но через пару месяцев загляните
  в Actions. Если запуски остановились, нажмите Enable workflow.

## Файлы

- `bot.py` — публикация одного поста и выбор следующего из очереди
- `build_passages.py` — сбор отрывков с иллюстрациями из книг Standard Ebooks
- `llm.py` — запросы к Gemini
- `common.py` — формат подписи, проверки и настройки
- `books.json` — список книг
- `passages.json` и папка `images/` — банк отрывков; `state_passages.json` — очередь (обновляется ботом)
- `.github/workflows/post.yml`, `.github/workflows/build.yml` — запуск публикации и пополнения банка
