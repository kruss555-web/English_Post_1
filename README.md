# English Quiz Bot — ТЕСТОВАЯ версия (DEV)

Это отдельный репозиторий для обкатки новых видов постов. Он **ничего не знает о рабочем канале**:
свой бот, свой тестовый канал, своё состояние. Расписания здесь нет, всё запускается только вручную.
Рабочий репозиторий с двумя опросами в день этим пакетом не затрагивается.

В пакете (по сравнению с рабочей версией):
- опросники (как в рабочем канале) и **отрывки из классики с иллюстрацией** (новое);
- строка «уровень · тема» без эмодзи, с переключателем `LEVEL_LINE` (см. ниже);
- `promote/bot.prod.yml` — готовый боевой workflow с расписанием 08:00 / 15:00 / 02:30 UTC для момента переноса.

## Настройка (один раз)

**1. Тестовый бот и канал**
1. @BotFather → `/newbot`: **новый** бот, не рабочий. Токен скопируйте.
2. Создайте закрытый тестовый канал и добавьте бота администратором с правом публиковать.
3. У закрытого канала нет `@username`, поэтому нужен числовой id вида `-100…`. Как получить:
   опубликуйте в канале любое сообщение, затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите в ответе `"chat":{"id":-100…`.
   (Если в ответе пусто, отправьте в канал ещё одно сообщение и обновите страницу.)

**2. Ключ Gemini**
По возможности создайте его в **новом проекте** Google AI Studio. Лимиты бесплатного уровня обычно считаются
на проект, и тогда тесты не съедают суточную квоту рабочего канала. Если ключ общий, генерируйте здесь
понемногу (`count` 5–10).

**3. Репозиторий**
1. На github.com создайте новый репозиторий, например `english-channel-dev` (публичный, как и рабочий).
2. Add file → Upload files → загрузите всё содержимое этого архива, включая папку `.github`.
3. Проверьте, что есть `.github/workflows/bot.yml`. Если папка не загрузилась (она скрытая):
   Add file → Create new file, имя `.github/workflows/bot.yml`, вставьте содержимое файла.

**4. Секреты** (Settings → Secrets and variables → Actions → New repository secret):

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен **тестового** бота |
| `TELEGRAM_CHAT_ID` | id тестового канала (`-100…`) |
| `GEMINI_API_KEY` | ключ Gemini |

## Что проверять (Actions → English Quiz Bot (DEV) → Run workflow)

1. `post` → в тестовом канале опрос. Смотрим строку уровня и пояснение.
2. `build-passages`, `count = 5` → в логе у каждой книги написано, сколько найдено иллюстраций.
   Если у книги 0 или картинки не те, замените её в `books.json` (номер книги виден в адресе страницы на gutenberg.org).
3. `passage` → пост с картинкой, текстом с пропусками, вариантами и ответом под спойлером.
   Пока банк отрывков пуст, вместо отрывка публикуется викторина.
4. Просмотрите 10–20 отрывков: подходит ли картинка к тексту, нет ли неоднозначных вариантов.
5. Эксперимент со строкой уровня: Settings → Variables → `LEVEL_LINE` = `description`, затем `post`.
   Telegram покажет уровень в описании опроса (где именно и как выглядит, зависит от приложения).
   Не понравилось: удалите переменную или поставьте `question`. Если Telegram не примет описание,
   бот сам опубликует уровень в вопросе.

Другие настройки (Variables): `TARGET_SIZE`, `PASSAGES_TARGET`, `EXPLANATION_LANG`, `GEMINI_MODEL`.
Размер картинки: `CANVAS_W`, `CANVAS_H` в `common.py` (по умолчанию 16:9). Что показывать под спойлером:
`SHOW_EXPLANATION`, `SHOW_SOURCE` там же.

## Как добавлять новое (правило независимости)

Тестовый репозиторий и тестовый канал остаются песочницей навсегда. Новый вид поста сначала пишется и
проверяется только здесь. В рабочий репозиторий попадает код (но не данные), и только отдельным осознанным
шагом (ниже). Пока этого шага нет, рабочий канал работает как раньше.

## Перенос в рабочий канал (когда всё устраивает)

Расписания GitHub запускаются только с основной ветки (`main`), поэтому безопасный порядок такой:

1. В **рабочем** репозитории загрузите файлы в **новую ветку**: Add file → Upload files, внизу выберите
   «Create a new branch for this commit». Пока ветка не слита, рабочий канал продолжает работать со старыми файлами.
2. Что копировать: `bot.py`, `common.py`, `generate.py`, `build_passages.py`, `books.json`
   и, если переносите отрывки, `passages.json` и папку `images/` (так не придётся заново тратить лимит Gemini
   на уже проверенные отрывки). Файл `state_passages.json` в рабочем репозитории создайте **пустым**, с содержимым `{}`:
   если взять его из тестового, отрывки, показанные в тестовом канале, будут считаться уже опубликованными.
3. Что **не** копировать: `questions.json` и `state.json`. Это данные рабочего канала (накопленные вопросы и очередь).
   Если их затереть, вопросы начнут повторяться с начала.
4. Workflow: содержимое `promote/bot.prod.yml` вставьте в `.github/workflows/bot.yml` рабочего репозитория
   (в той же ветке). Время в нём 08:00 и 15:00 UTC. Если меняете время, поменяйте его и в `cron`, и в условиях `if:`;
   проверка в начале файла подскажет, если они разошлись.
5. Слейте ветку (Pull request → Merge). Затем сразу запустите вручную `post` и убедитесь, что пост вышел.
6. Откат: в рабочем репозитории отмените коммит слияния (Revert), и всё вернётся как было.

## Файлы

- `bot.py` — публикация одного поста (викторина или отрывок)
- `generate.py` — генерация вопросов
- `build_passages.py` — сбор отрывков с иллюстрациями из Project Gutenberg
- `common.py` — общие функции и настройки
- `books.json` — книги для отрывков
- `questions.json`, `passages.json`, `images/` — банки; `state.json`, `state_passages.json` — очереди
- `promote/bot.prod.yml` — боевой workflow для переноса
